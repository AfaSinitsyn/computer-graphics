# Лабораторная № 2: камера и освещение

## 1. Что изменилось после первой лабы

Раньше фрагмент получал цвет, интерполированный между вершинами.
Теперь у вершины есть нормаль, а фрагментный шейдер вычисляет освещение
по положению поверхности, её нормали, положению камеры и параметрам света.
Объект остался тем же: параллелепипед варианта 3.

Основа реализации — лекция № 4 «Lighting & materials» и задание «Camera and Lighting».
Статья [LearnOpenGL: Light casters](https://learnopengl.com/lighting/light-casters)
используется для идеи трёх типов источников и мягкой границы прожектора.
API остаётся Vulkan. По заданию используем именно `1 / d²`, а не общую формулу
`1 / (constant + linear*d + quadratic*d²)` из статьи.

## 2. Камера и матрицы

Камера задаёт позицию и три угла. Как и в первой лабе, она смотрит вдоль локальной +Z.
Её матрица в мире:

```text
C = T * Rz * Ry * Rx
```

Чтобы получить координаты относительно камеры, нужна обратная матрица:

```text
V = inverse(C) = Rx(-x) * Ry(-y) * Rz(-z) * T(-position)
```

В `lab_scene.hpp`, функция `viewMatrix()`, это записано без общей функции обращения
матрицы 4×4: обратные перенос и повороты известны, остаётся поменять порядок.
`updateUniforms()` в `application.cpp` вычисляет `P * V` для сцены и `M` для модели.
Вершинный шейдер получает итоговую позицию как `P * V * M * position`.

## 3. Нормали

Нормаль — перпендикуляр к поверхности. Для трёх вершин грани:

```text
N = normalize(cross(B - A, C - A))
```

`makeParallelepiped()` вычисляет её процедурно для каждой грани. Углов геометрически
по-прежнему восемь, но нужны 24 записи вершин: одна позиция на стыке трёх граней
используется с тремя разными нормалями. Это сохраняет плоские грани и резкие рёбра.

В вершинном шейдере нормаль преобразуется через `transpose(inverse(mat3(M)))`.
Так она остаётся перпендикулярной грани при неравномерном масштабе объекта.
После интерполяции во фрагментном шейдере нормаль нормализуется повторно.

## 4. Блинн—Фонг

Всё освещение считаем в мировых координатах. Обозначения:

- `N` — единичная нормаль;
- `L` — единичное направление от поверхности к источнику;
- `V` — единичное направление от поверхности к камере;
- `H = normalize(L + V)` — половинный вектор;
- `albedo` — цвет диффузной части материала;
- `specular` — цвет блика;
- `shininess` — показатель степени, определяющий ширину блика.

Функция `blinnPhong()` в `parallelepiped.frag`:

```text
diffuse = max(dot(N, L), 0)
specularFactor = pow(max(dot(N, H), 0), shininess)
result = radiance * (albedo * diffuse + specularColor * specularFactor)
```

Блик вычисляется только на освещённой стороне (`dot(N,L) > 0`). Чем больше
`shininess`, тем меньше и резче блик. Ambient прибавляется один раз для всей сцены:
`albedo * ambientColor * ambientIntensity`.

## 5. Источники

### Направленный

Лучам задано общее направление. Позиции и затухания по расстоянию нет.
В шейдере `L = -normalize(direction)`, потому что direction указывает вдоль лучей,
а `L` должен указывать от поверхности к источнику.

### Точечный

```text
toLight = lightPosition - worldPosition
distanceSquared = dot(toLight, toLight)
L = normalize(toLight)
radiance = lightColor * intensity / distanceSquared
```

В знаменателе есть маленький нижний предел для защиты от деления на ноль
прямо в источнике. При удвоении расстояния свет ослабевает в четыре раза.

### Прожектор

Сначала считаем точечный свет, затем умножаем его на коэффициент конуса:

```text
theta = dot(-L, normalize(direction))
cone = clamp((theta - cos(outer)) / (cos(inner) - cos(outer)), 0, 1)
```

Внутри внутреннего конуса коэффициент равен 1, снаружи внешнего — 0,
между ними он плавно меняется. Если углы равны, используем жёсткую границу,
чтобы не делить на ноль. В GUI задаются половинные углы конуса.

## 6. Дескрипторы и буферы

| Набор | Binding | Ресурс | Данные |
|---|---|---|---|
| `set=0`, сцена | 0 | Uniform buffer, std140 | view-projection, камера, ambient, направленный свет, количества источников |
| `set=0`, сцена | 1 | Storage buffer, std430 | массив точечных источников |
| `set=0`, сцена | 2 | Storage buffer, std430 | массив прожекторов |
| `set=1`, модель | 0 | Uniform buffer, std140 | матрица модели, альбедо, цвет блика и блеск |

`createDescriptors()` создаёт два layout, пул и два набора. `updateUniforms()`
переписывает данные. `render()` привязывает оба набора перед `vkCmdDrawIndexed()`.

На CPU источники хранятся в `std::vector`. В storage buffer в шейдере объявлен
массив `lights[]` без фиксированного числа элементов. Число активных источников
лежит в uniform buffer сцены. При росте массива пересоздаётся его VkBuffer
и обновляется соответствующий дескриптор. Ограничение задаётся возможностями
устройства (`maxStorageBufferRange`), а не константой в шейдере.

Данные представлены полями размером vec4, чтобы выравнивание C++ и GLSL совпадало.
Даже для пустого массива создаётся буфер размером в один элемент — Vulkan не разрешает
нулевой размер. Счётчик равен нулю, поэтому шейдер такой элемент не читает.
В стартовом цикле `prepare()` ждёт fence предыдущего кадра до `update()`,
поэтому перезаписываемые данные уже не используются предыдущей отрисовкой.

## 7. Что открыть преподавателю

1. Запустить программу: показать камеру, материал, ambient и направленный источник.
2. Убавить направленный свет до 0, добавить точечный источник, менять его положение
   и интенсивность. Добавить второй, затем удалить: число источников действительно меняется.
3. Удалить точечные, добавить прожектор. Менять направление, внутренний и внешний углы;
   показать мягкую границу на поверхности. При необходимости уменьшить углы до 5°/15°.
4. `source/lab_scene.hpp`: `makeParallelepiped()`, `viewMatrix()`, структуры GPU.
5. `source/application.cpp`: `createDescriptors()`, `updateUniforms()`, `render()`.
6. `shaders/parallelepiped.vert`: мировые координаты и нормаль.
7. `shaders/parallelepiped.frag`: `blinnPhong()`, цикл точечных и цикл прожекторных источников.

Пояснение одной фразой: «Использовал свою первую лабораторную на каркасе преподавателя;
добавил управляемую камеру, нормали, материалы и три типа света; общие данные сцены
и данные модели разделены на два набора дескрипторов».

Реализованы базовое задание и дополнительные 1–3 (уровень на 4).
Визуализация источников отдельными кубами/сферами и конусами относится к заданию на 5.
